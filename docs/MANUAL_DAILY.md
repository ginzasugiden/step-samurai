# ステップ侍 利用マニュアル②：日常運用編（毎日〜毎週の作業）

初期設定がまだの方は、先に `MANUAL_SETUP.md`（初期設定編）を終えてください。このマニュアルは、日々の確認作業・トラブル対応・用語の確認に使います。

---

## 0. 緊急停止手順（まずここだけは覚えておいてください）

「メールが変な内容で送られている」「お客様から問い合わせが来た」など、**今すぐ送信を止めたいとき**は、以下のどちらかを行ってください。どちらも数分あれば完了します。

### 方法A：DRY_RUNをtrueに戻す（最も早く確実。まずこちらを推奨）

1. GASエディタ左メニューの歯車アイコン「プロジェクトの設定」をクリックする。
2. 「スクリプト プロパティ」の一覧から `DRY_RUN` を探す。
3. 値を `true` に書き換えて保存する。
   - なぜ：`DRY_RUN`は毎回リアルタイムで読み込まれる値のため、次にステップ侍が動いた瞬間から、メール送信・クーポン発行が一切行われなくなります（待ち時間はありません）。
   - 効果の範囲：**今まさに実行中の処理**が動いている場合、その回だけは最後まで終わる可能性があります。完全に止めたい場合は方法Bも合わせて行ってください。

### 方法B：トリガーを削除する（次の自動実行そのものをなくす）

1. GASエディタ左メニューの時計アイコン「トリガー」をクリックする。
2. 止めたいトリガー（`runHourlyFollowPipeline`など）の行を探し、右側の「⋮」（縦三点リーダー）から「トリガーを削除」を選ぶ。
   - なぜ：トリガーが無くなれば、そもそも自動実行そのものが起こらなくなります。

**元に戻す方法：** 原因が解決したら、方法Aは`DRY_RUN`を`false`に戻す、方法Bは`MANUAL_SETUP.md`7章の手順で`runHourlyFollowPipeline`のトリガーを再登録すれば、通常運用に戻ります。**再開前に、原因が本当に解決したか必ず確認してください。**

## 1. 毎日確認すること

店舗専用スプレッドシートを開き、以下のタブを確認してください。

| 確認したいこと | 見るタブ | 見るポイント |
|---|---|---|
| メールがちゃんと送られているか | `sends`タブ | 一番下（最新）の行の`result`列。`sent`なら成功、`error: ...`で始まっていれば失敗（3章FAQ参照） |
| いつ・誰に・どの文面が送られたか | `sends`タブ | `sent_at`（送信日時）、`type`（`follow`＝お礼メール／`coupon`＝クーポンメール）、`template_id`列 |
| 新しい注文が正しく取り込めているか | `orders`タブ | 最新の注文が`order_number`列に増えているか、`ship_date`（発送日）が空欄のままの行が無いか |
| クーポン発行状況（準備中のため通常は空） | `coupons`タブ | 準備中の機能のため、基本的には空のままのはずです |

エンジニアが管理画面（Web UI）を用意している場合は、ブラウザでログインし、上部の **「履歴」タブ** から同じ内容（メール送信・クーポン発行の直近50件）を確認できます。

【スクショ: sendsタブの一覧（result列に注目）】

**GASの実行ログでも確認できます。** GASエディタ左メニューの「実行数」（実行アイコン）から、直近の`runHourlyFollowPipeline`の実行が正常終了しているか、エラーが出ていないかを見ることができます。

## 2. テスト運用の3段階（「試着→試食→開店」で考える）

いきなり本番でお客様にメールを送るのではなく、次の3つの段階を順番に踏むことを強く推奨します。それぞれ、身近な例に置き換えるとこうなります。

### 第1段階：DRY_RUN（試着）

服を試着するだけで、まだお金を払って買ってはいない状態です。ステップ侍は「このお客様に、この件名・本文でメールを送ります」という内容をログに書き出すだけで、**実際には誰にも一通も届きません。**

- 設定：`DRY_RUN` = `true`
- 確認すること：GASの実行ログに出る `[DRY_RUN]` から始まる行を見て、対象件数・宛先・件名が想定通りかを確認する。
- この段階で問題があれば：`MANUAL_SETUP.md`のsettings/templatesの設定を見直し、何度でもやり直してよい段階です（実害がないため）。

### 第2段階：TEST_MAIL_TO（試食）

作った料理を、お客様に出す前に自分で味見する状態です。実際にメール送信の仕組みが動きますが、**宛先は強制的にあなた（担当者）のメールアドレスに差し替えられる**ため、お客様には絶対に届きません。

- 設定：`DRY_RUN` = `false`、`TEST_MAIL_TO` = 自分の（テスト用の）メールアドレス
- 確認すること：実際に自分のメールボックスに届いたメールを開き、件名・本文・差し込みタグ（`{{buyer_name}}`など）が正しい文章に置き換わっているか、レイアウトが崩れていないかを目で見て確認する。
- 注意：この段階で件名や本文がおかしい場合は、`MANUAL_SETUP.md`5章の手順で文面を直してから、もう一度テスト送信をやり直してください。

### 第3段階：本番（開店）

お店を開けて、実際のお客様に商品・サービスを届ける状態です。

- 設定：`DRY_RUN` = `false`、`TEST_MAIL_TO` = 空欄
- この状態にして初めて、実際のお客様にメールが届きます。**この切り替えは、第1・第2段階で問題が無いことを確認してから行ってください。**
- 本番切り替え後は、しばらくの間（少なくとも数日）は「1. 毎日確認すること」の内容を毎日チェックすることを強く推奨します。

## 3. よくあるトラブルと対処法（FAQ）

### Q1. メールが届かない

考えられる原因を、上から順に確認してください。

1. **`DRY_RUN`が`true`のままになっていないか。** → `true`の間は仕組み上、絶対にメールは届きません（0章「試着」の状態です）。GASエディタの「プロジェクトの設定」で確認してください。
2. **`TEST_MAIL_TO`が設定されたままになっていないか。** → 設定されている間は、お客様にではなく、そこに書かれたアドレスにだけ届きます。不要になったら空欄に戻してください。
3. **`sends`タブに`error: ...`という記録が無いか。** → メール送信サービス（SMTPブリッジ）との通信に失敗している可能性があります。`BRIDGE_URL`・`BRIDGE_SECRET`が正しいか、`MANUAL_SETUP.md`3章の`config.php`の内容とサーバー側の状態をエンジニアに確認してもらってください。
4. **その注文が発送日から必要日数を過ぎていないか。** → `settings`タブの`follow_days_after_ship`で指定した日数が経過するまでは、まだ送信対象になりません。
5. **その注文の`ship_date`（発送日）が空欄になっていないか。** → 発送日が空欄の注文は、仕組み上フォローメールの対象から外れます。楽天RMS側の出荷情報が正しく登録されているか確認してください。
6. **`EXCLUDE_ORDERS`にその注文番号が入っていないか。** → 一時的な緊急除外リストに入っていると、その注文だけ送信対象から外れます（`MANUAL_SETUP.md`6章参照）。
7. **すでに送信済みではないか。** → `sends`タブにその注文番号・種類（`follow`）の行があり、`result`が`error`で始まっていなければ、二重送信を防ぐ仕組みにより「送信済み」として扱われ、再送されません。

### Q2. 対象0件と出る

GASの実行ログや管理画面で「対象0件」と表示される場合、次のいずれかが原因です。

- **`GO_LIVE_DATE`（サービス開始日）が未設定、または不正な値になっている。** → 安全のため、この設定が読み取れないと「対象0件」として全件スキップする仕組みになっています。`MANUAL_SETUP.md`6章の手順で値を確認してください。
- **`settings`タブの`follow_days_after_ship`が空欄、または数値として認識できない値になっている。** → 同様に安全のため全件スキップされます。
- **単純に、まだ発送から必要日数がたった注文が無い。** → お店を始めたばかりの場合や、直近に発送した注文しかない場合は、これが正常な状態です。

### Q3. エラーメールが届いた

件名が「[step-samurai] 通知」というメールが`ADMIN_EMAIL`宛てに届くことがあります。これは、自動処理の途中で予期しない問題が起きたときの通知です。

- 本文に「パイプラインエラー」と書かれている場合：受注取得やメール送信などの一連の処理のどこかで、予想外のエラー（楽天側の一時的な通信エラー、設定ミスなど）が発生したことを示します。よくある原因として、マスター管理シートに店舗のメールアドレス（`shop_email`）が未設定、または楽天RMSの認証情報を保存したシートにその店舗の行が見当たらない、というケースがあります。エラー文の内容を確認し、`MANUAL_SETUP.md`3〜6章の設定を見直してください。
- 本文に「runHourlyFollowPipelineエラー」と書かれている場合も同様です。

### Q4. ライセンスキーの期限が切れた（切れそう）という通知が来た

「【step-samurai】（店舗名）のRMSライセンスが◯日後に失効します」、または「RMSライセンスは失効済みです」という通知は、毎日午前9時に自動でチェックされる仕組みから送られています。これは`MANUAL_SETUP.md`3章で取得したlicenseKeyの有効期限が近づいている（または切れている）ことを知らせるものです。

- 対処法：楽天RMSの管理画面から、WEB APIサービスのlicenseKeyを更新（再発行）し、`MANUAL_SETUP.md`6章の`API_KEY_SHEET_ID`が指すシート内の該当する値を新しいものに差し替えてください。
- 放置するとどうなるか：期限が切れると、注文データの取得やメール送信がすべて失敗するようになります。

### Q5. 文面を保存したら「未知のプレースホルダが含まれています」と警告が出た

`MANUAL_SETUP.md`5章の差し込みタグ一覧に無い`{{◯◯}}`という文字が本文・件名に含まれているときに出る警告です。多くの場合、タグの綴りミス（`{{buyer_nam}}`など）が原因です。表と見比べて、正しいタグ名に直してください。**警告が出ても保存自体は成功してしまう点に注意してください。** そのまま放置すると、お客様に届くメールに`{{buyer_nam}}`のような文字がそのまま表示されてしまいます。

### Q6. settingsタブ・管理画面で保存しても反映されない／「編集不可」と出る

`coupon_rules`など、一部の設定項目は`editable_by_tenant`が`FALSE`になっており、店舗側からは変更できないよう保護されています（`MANUAL_SETUP.md`4章参照）。意図的な保護なので、変更したい場合はエンジニアに相談してください。

## 4. 用語集（五十音順）

| 用語 | 意味 |
|---|---|
| あんしんメルアド | お客様へのメール送信を代行してくれる、メール送信サービスの名称。ステップ侍は直接メールを送るのではなく、このサービスを経由して送信する |
| API（エーピーアイ） | お店のシステムと楽天のシステムが、人を介さずに直接データをやり取りするための専用の窓口 |
| SMTPブリッジ（ブリッジ） | ステップ侍からのメール送信依頼を受け取り、あんしんメルアドなど実際のメール送信サービスへ橋渡しする仕組み |
| GAS（ジーエーエス） | Googleが無料で提供している、自動で作業してくれるロボットを作るための仕組み。ステップ侍の本体はこれで作られている |
| クーポン | レビュー投稿の特典として次回注文で使える割引。**現在準備中で自動発行はまだ行われない** |
| serviceSecret（サービスシークレット） | licenseKeyとセットで使う、楽天へのもう1つの合言葉 |
| 差し込みタグ（プレースホルダ） | メール文面の中に書く `{{buyer_name}}` のような記号。送信時に自動でお客様ごとの情報に置き換わる |
| Script Properties（スクリプト プロパティ） | ステップ侍の「設定金庫」。パスワードのような大事な値やON/OFFスイッチを保管する場所 |
| スプレッドシート | Googleが提供する、Excelのような表計算ソフト。注文データや文面はここに保存されている |
| settings（設定タブ） | 店舗専用スプレッドシート内にある、フォローメールの送信日数などの運用ルールを書き込むタブ |
| テナント | ステップ侍を利用する店舗1つ1つのことを指す言葉（プログラム内部の呼び方） |
| templates（文面タブ） | 店舗専用スプレッドシート内にある、メールの件名・本文を書き込むタブ |
| デプロイ | GASで作ったプログラムを、実際に外部から呼び出せる状態にして公開する操作 |
| DRY_RUN（ドライラン） | 「試運転モード」のこと。`true`の間はメール送信・クーポン発行を一切実行せず、ログに記録するだけになる安全装置 |
| トリガー | 「決まった時間になったら自動でこの処理を実行して」という、目覚まし時計のような仕組み |
| フェイルクローズ | 「設定値が読み取れない・おかしいときは、危険なことはせず、何もしない」という安全設計の考え方。ステップ侍では対象0件・送信スキップという形で現れる |
| ライセンスキー | serviceSecretとセットで使う、楽天への合言葉。有効期限があり、切れると注文データの取得ができなくなる |
| レビュー連携（review_linked） | お客様が投稿したレビューと、注文データを結びつける処理のこと。クーポン発行（準備中）の判定条件の1つとして使われる |
