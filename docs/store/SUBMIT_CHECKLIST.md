- [ ] `for f in tests/*.js; do node $f; done` が全件 pass
- [ ] `node tools/build-extension.js` で `dist/step-samurai-review-ext-1.0.0.zip` を再生成した
- [ ] zip のエントリがスラッシュ区切りで、ルートに `manifest.json` がある（`tar -tf dist/step-samurai-review-ext-1.0.0.zip` で確認。tests / tools / docs は含まない）
- [ ] 実機で `extension/` を読み込み、設定画面・ポップアップが動く（テスト用テナントで「送信テスト」が「接続OK」）
- [ ] 本番 GAS の受け口（`ext_ingest_reviews`）がデプロイ済み（`CLAUDE.md` の clasp デプロイ手順）

- [ ] 規約・ガイドの改定（設計書 §6）が反映済み

## 1. デベロッパー登録（初回のみ）

- [ ] Chrome ウェブストア デベロッパー ダッシュボード（https://chrome.google.com/webstore/devconsole）に、公開用の Google アカウントでログイン
- [ ] 登録料（一度きり）を支払う
- [ ] 公開者名（株式会社GSD）・連絡用メールを登録し、メールアドレスを確認済みにする（ストアの要件。連絡先は一般に公開される）
- [ ] **アカウントの 2 段階認証を有効にする**（拡張機能の公開に必須）

## 2. 新しいアイテムの作成

- [ ] 「新しいアイテム」から `dist/step-samurai-review-ext-1.0.0.zip` をアップロード
- [ ] アップロードエラー（manifest の問題など）が出ないこと

## 3. ストア掲載情報

- [ ] `LISTING.md` の短い説明・詳細説明・カテゴリ（仕事効率化）・言語（日本語）を入力
- [ ] アイコン（128x128）・スクリーンショット（`SCREENSHOTS.md`）をアップロード
- [ ] 公開者名が「株式会社GSD」で表示される

## 4. プライバシー

- [ ] 単一目的の説明を入力（`LISTING.md`）
- [ ] 権限ごとの正当化を入力（`PERMISSIONS.md`）。host 3 つ、storage、alarms
- [ ] リモートコードを使用していない、を選択（`PERMISSIONS.md`）
- [ ] データ使用の開示を入力し、3 つの宣言にチェック（`DATA_DISCLOSURE.md`）
- [ ] プライバシーポリシーの URL を入力（`PRIVACY_POLICY_URL.md`）

## 5. 公開設定

- [ ] 公開設定を **「限定公開（Unlisted）」** にする（「非公開」でも「公開」でもない）
- [ ] 対象地域は全地域のまま（または日本のみ。運用で決める）
- [ ] 公開のタイミングは「審査通過後に手動で公開」を選ぶと、承認後に公開日を決められる

## 6. ここで止める

- [ ] 入力内容を全画面で見直す（権限・説明・データ開示が `extension/manifest.json` の実装と一致しているか）
- [ ] 「審査のために送信」は押さず、担当者に確認を依頼する
- [ ] 承認が出たら、限定公開のリンクを店舗へ案内する文面を用意する（トークンの配布は別経路）

## 参考

- 審査には数日以上かかる。RMS の仕様変更への即応は、更新の審査があるため難しい。拡張は変更時に「何も送らず停止」する作りになっている。
