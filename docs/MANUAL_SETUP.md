# ステップ侍 利用マニュアル①：初期設定編（最初に1回だけ行う作業）

このマニュアルは、プログラミングの知識が無い方でも、上から順番に読んで操作すれば設定が完了するように書かれています。専門用語が出てきたときは、その場で1行の説明を入れています。

わからない言葉が出てきたら、姉妹編の `MANUAL_DAILY.md`（日常運用編）の末尾にある「用語集」も参考にしてください。

---

## 0. まず知っておくこと

- このマニュアルの手順は「1回だけ」やれば基本的に完了します。毎日の操作については `MANUAL_DAILY.md`（日常運用編）を見てください。
- 手順の中には「エンジニア（コードを扱える人）に頼んだほうがよい作業」も含まれます。そういう箇所には **【エンジニア向け】** と明記します。それ以外は店舗スタッフの方だけで完結できます。
- クーポンを自動で発行する機能は、**現在まだ準備中で使えません。** このマニュアルでは設定手順を書きません（理由は8章で説明します）。

## 1. ステップ侍とは何か

ステップ侍は、ひとことで言うと「**お客様が商品を受け取ったあと、自動でお礼メール（フォローメール）を送ってくれる仕組み**」です。人が毎回メールを書いて送る必要がありません。

流れを図にすると、こうなります。

```
①お客様が楽天市場で商品を注文する
        ↓
②お店が商品を発送する（発送日を記録）
        ↓
③発送から一定の日数がたつ（例：5日後）
        ↓
④ステップ侍が自動で「お礼＋ご感想をお聞きするメール」を送る
        ↓
⑤お客様がレビューを書いてくれる
        ↓
⑥（準備中）ステップ侍が自動で「次回使えるクーポン」を届ける
```

②〜④の部分は、ステップ侍が1時間ごとに自動で目を覚まして、「発送から○日たった注文はないか」をチェックしている、とイメージしてください。この「決まった間隔で自動的に動く」仕組みのことを、次のように呼びます。

> **トリガー**＝「毎時0分になったら自動でこの処理を実行して」という、目覚まし時計のような仕組みのことです。人がボタンを押さなくても、設定した時間になると自動で動きます。

ステップ侍の本体は、**GAS（ジーエーエス／Google Apps Script）** という、Googleが無料で提供している「自動で作業してくれるロボットを作る仕組み」の上で動いています。注文データやメールの文面は、Googleの表計算ソフトである**スプレッドシート**（Excelのようなもの）に保存されます。

お店のシステムと楽天のシステムが、人を介さずに直接データをやり取りする専用の窓口のことを **API（エーピーアイ）** と呼びます。ステップ侍は、この「楽天のAPI」を使って注文情報を取得しています。

## 2. 用意するもの一覧

設定を始める前に、以下を手元に用意してください。

1. **Googleアカウント**（スプレッドシートとGASを動かすために必要です）
2. **楽天RMS（楽天市場の店舗管理画面）の管理者ログイン情報**（WEB APIの申込み・認証情報の取得に必要です）
3. **あんしんメルアド、またはお使いのメール送信サービスのSMTP接続情報**（サーバー名・ポート番号・ユーザー名・パスワード。3章で使います）
4. **お客様に届くメールの「差出人」にしたいメールアドレス**
5. （サーバーへのファイル設置やGASプロジェクトの操作を任せる場合）**エンジニアへの連絡手段**

## 3. 楽天RMS側の準備

ステップ侍が楽天の注文データを取得するには、楽天RMS側で「WEB API」という機能を使えるようにし、専用の認証情報（合言葉）を発行してもらう必要があります。

> **licenseKey（ライセンスキー）・serviceSecret（サービスシークレット）**＝ステップ侍が「私は正規のお店のシステムです」と楽天に証明するための、2つセットの合言葉です。この2つを組み合わせて楽天のシステムに送ることで、注文データを取得する許可がもらえます。

### 3-1. WEB APIサービスを申し込む

1. 楽天RMSにログインする。
   - なぜ：これ以降の作業はすべてRMSの管理画面上で行うためです。
2. RMSの画面内で「WEB API」と検索するか、拡張機能・API連携に関するメニューを探し、WEB APIサービスの利用申込みを行う。
   - なぜ：申込みをしないとlicenseKey・serviceSecretが発行されません。
   - 【要確認】RMSのメニュー名称・配置は楽天側の仕様変更で変わることがあるため、本マニュアルでは正確な最新のメニュー名を保証できません。見つからない場合は、RMSのヘルプ内検索、または楽天市場の店舗運営者向けサポート窓口に「WEB APIサービスの申込み方法を知りたい」と問い合わせてください。
   - 失敗するとどうなるか：申込みが完了していない状態でステップ侍を動かすと、注文データの取得（後述のfetchOrders処理）がすべて失敗し、メールも一切送られません。

【スクショ: 楽天RMSのWEB APIサービス申込み画面】

3. 申込みが完了したら、licenseKeyとserviceSecretが発行されるので、両方をメモまたはコピーする。
   - なぜ：この2つの値は、次の章でスプレッドシートに登録する必要があるためです。
   - 注意：この2つの値は「合言葉」であり、他人に見せたり、メールやチャットで平文のまま送ったりしないでください。漏れると第三者が注文データを見られてしまう可能性があります。

【スクショ: licenseKey・serviceSecretの発行完了画面】

### 3-2. あんしんメルアド（メール送信サービス）のSMTP設定情報を確認する

お客様へのメール送信は、ステップ侍が直接行うのではなく、「あんしんメルアド」などのメール送信サービスを経由して行われます。この経由の仕組みを **SMTPブリッジ**（ブリッジ＝橋渡し役）と呼びます。

1. あんしんメルアド（またはお使いのメール送信サービス）の管理画面にログインする。
2. SMTP接続に必要な次の4つの情報を確認し、メモする。
   - サーバー名（ホスト名）
   - ポート番号
   - ユーザー名
   - パスワード
   - なぜ：この4つの情報がないと、メールを実際に送信するサーバー側の設定ファイルが作れません。
3. メモした4つの情報を、サーバー設置作業を行うエンジニアに渡す。

**【エンジニア向け】** ここから先はサーバー（ロリポップ等のレンタルサーバー）へのファイル設置作業のため、多くの場合エンジニアが行います。本リポジトリの `bridge/config.example.php` を `config.php` としてコピーし、以下の項目に実際の値を入れてサーバーに設置してください。

| 設定項目 | 意味 |
|---|---|
| `bridge_secret` | ステップ侍側の `BRIDGE_SECRET`（7章参照）と**必ず同じ値**にする合言葉。値が一致しないとメール送信が拒否される |
| `smtp_host` | あんしんメルアドのサーバー名 |
| `smtp_port` | ポート番号（例：587） |
| `smtp_user` | あんしんメルアドのユーザー名 |
| `smtp_password` | あんしんメルアドのパスワード |
| `smtp_encryption` | 暗号化方式（`tls` または `ssl`） |

失敗するとどうなるか：`config.php` の内容が間違っている、または未設置の場合、メール送信時に「Bridge error」というエラーがログに記録され、お客様にメールが届きません（詳しい対処は `MANUAL_DAILY.md` のFAQ参照）。

## 4. スプレッドシートの設定（settingsシート）

ステップ侍は、お店ごとに専用のスプレッドシート（表）を1つ持っています。その中の **「settings」というタブ（シート下部のタブ）** に、運用ルールを書き込みます。

> **タブ**＝Excelやスプレッドシートの画面下にある、複数のシートを切り替えるための見出し部分のことです。

【スクショ: テナント用スプレッドシートの「settings」タブ】

settingsタブには、`key`（キー＝項目名）・`value`（値）・`description`（説明）・`editable_by_tenant`（店舗側で編集してよいか）という4つの列があります。実際に入っている項目は次のとおりです。

| key（項目名） | 意味 | 記入例 | 店舗側で編集してよいか |
|---|---|---|---|
| `follow_days_after_ship` | 商品を発送してから何日後にお礼メール（フォローメール）を送るか（日数） | `5` | ○ 編集可（`editable_by_tenant`が`TRUE`） |
| `coupon_valid_days` | クーポンの有効期間（発行から何日間使えるか）。**クーポン機能自体が準備中のため、現時点では未使用の項目です** | `30` | ○ 編集可（`editable_by_tenant`が`TRUE`） |
| `coupon_rules` | クーポンの割引条件を細かく指定するための設定（JSON形式という、プログラム同士がやり取りする専用の書式）。**クーポン機能が準備中のため今は使いません** | （変更しない） | ✕ 編集不可（`editable_by_tenant`が`FALSE`）。**うっかり書き換えると壊れて正しく読み込めなくなるため、絶対に触らないでください** |

### 4-1. 手順：follow_days_after_shipを設定する

1. 店舗専用スプレッドシートを開き、下部の「settings」タブをクリックする。
   - なぜ：フォローメールの送信タイミングはこのタブで管理されているためです。
2. `follow_days_after_ship` の行を探し、`value`列のセルをクリックする。
3. 送りたい日数（例：`5`）を半角数字で入力する。
   - なぜ：全角数字や「5日」のような文字混じりの値だと、システムが数値として認識できず、**フォローメールが1件も送られなくなります**（安全のため、判断できない値は「何もしない」動きになる設計です）。
4. Enterキーを押して確定する。
   - 失敗するとどうなるか：空欄のまま、またはマイナスの数値のままにすると、その店舗のフォローメール送信処理全体が止まります。
   - 間違えたときの戻し方：もう一度セルをクリックして正しい数値に上書きすればすぐに直ります。反映までの待ち時間はありません。

## 5. メール文面の作り方（templatesタブ）

同じスプレッドシートの **「templates」というタブ** に、メールの件名・本文が保存されています。

【スクショ: テナント用スプレッドシートの「templates」タブ】

templatesタブには `template_id`（どのメールか）・`subject`（件名）・`body`（本文）・`updated_at`（最終更新日時）の4つの列があります。あらかじめ2種類のメールが登録されています。

| template_id | どのメールか | 現在使えるか |
|---|---|---|
| `follow_v1` | 発送後に送る、お礼＋ご感想をお聞きするメール | ○ 使用中 |
| `coupon_v1` | レビュー投稿特典のクーポンをお知らせするメール | ✕ 準備中（クーポン機能自体が未稼働のため送信されません） |

### 5-1. 差し込みタグ（プレースホルダ）一覧

文面の中に `{{buyer_name}}` のような二重の波かっこで囲まれた文字を入れておくと、送信時に自動でお客様ごとの情報に置き換わります。これを**差し込みタグ（プレースホルダ）**と呼びます。

使えるタグは次の7種類だけです（これ以外の `{{◯◯}}` は自動で認識されず、そのままの文字として表示されてしまいます）。

| タグ | 置き換わる内容 | follow_v1（お礼メール）で使用 | coupon_v1（クーポンメール）で使用 |
|---|---|---|---|
| `{{buyer_name}}` | 購入者の名前（未設定の場合は「お客様」と表示） | ○ | ○ |
| `{{shop_name}}` | 店舗名 | ○ | ○ |
| `{{ship_date}}` | 発送日 | ○ | − |
| `{{discount}}` | クーポンの割引金額（円） | − | ○（準備中） |
| `{{coupon_valid_until}}` | クーポンの有効期限 | − | ○（準備中） |
| `{{coupon_get_url}}` | クーポンを受け取るためのURL | − | ○（準備中） |
| `{{shop_signature}}` | 署名欄（店舗名＋お問い合わせURL） | ○ | ○ |

### 5-2. 手順：お礼メール（follow_v1）の文面を編集する

1. templatesタブの `follow_v1` の行を探す。
2. `subject`列（件名）のセルをクリックし、内容を書き換える。
   - なぜ：ここがお客様に届くメールの件名になります。
3. `body`列（本文）のセルをダブルクリックすると、セル内に本文全体が表示されるので、そこで書き換える。
   - 失敗するとどうなるか：`{{buyer_nam}}` のようにタグの綴りを間違えると、そのタグは変換されずに `{{buyer_nam}}` という文字がそのままお客様に届いてしまいます（システム側はエラーにせず、気づかず送ってしまう可能性があるので特に注意してください）。
4. 編集する前に、元の文章をメモ帳などに一度コピーしておく。
   - なぜ：もし失敗しても、元の文面にすぐ戻せるようにするためです。スプレッドシートには「ファイル」メニューから変更履歴（過去の状態）を見る機能もありますが、念のため手元にも控えておくと安心です。
5. 編集が終わったら、`updated_at`列を今日の日付に更新する（任意）。
   - なぜ：いつ誰が編集したかの記録用です（システムの動作には影響しません）。

**別の編集方法（あれば）：** エンジニアが「管理画面（Web UI）」を用意している場合は、ブラウザで管理画面を開き、上部のタブから **「文面」タブ** をクリックすると、同じ内容をスプレッドシートを開かずに編集できます。画面上部に差し込みタグの一覧が表示され、保存ボタンを押すと「未知のプレースホルダが含まれています」という警告が出ることがあります。これは、使えないタグ（上の表に無いタグ）を書いてしまったときの注意メッセージです。警告が出た場合は、タグの綴りを表と見比べて確認してください。

## 6. Script Properties（設定金庫）の設定手順

**Script Properties（スクリプト プロパティ）**は、ステップ侍の「設定金庫」です。パスワードのような大事な値や、送信のON/OFFを切り替えるスイッチが、ここにまとめて保管されています。settings/templatesタブとは違い、こちらはGASの管理画面（GASエディタ）から操作します。

### 6-1. Script Propertiesの開き方

1. GASエディタ（ステップ侍のプロジェクトを開いた画面）の左側のメニューから、歯車のアイコン「プロジェクトの設定」をクリックする。
   - なぜ：ここにScript Propertiesの入力欄があるためです。
2. 画面を下にスクロールし、「スクリプト プロパティ」という項目を探す。
3. 「スクリプト プロパティを追加」ボタンをクリックし、プロパティ名（キー）と値を入力する。
   - なぜ：新しい項目を1つ追加する操作です。

【スクショ: GASエディタの「プロジェクトの設定」→「スクリプト プロパティ」画面】

この操作はステップ侍の動きを直接左右するため、**入力ミスをすると意図せずメールが送信されてしまう、または送信が全部止まってしまう可能性があります。** 表の内容をよく確認しながら1つずつ入力してください。

### 6-2. 設定するキー一覧

| キー名 | 意味 | 最初に入れる値（初期設定時） |
|---|---|---|
| `DRY_RUN` | 「試運転モード」のON/OFFスイッチ。`true`の間はメール送信・クーポン発行を一切実行せず、ログに記録するだけにする安全装置 | `true`（**最初は必ずこの値にする。詳しくは8章参照**） |
| `GO_LIVE_DATE` | この日付より前に発送された注文はメール送信の対象にしない、という区切り線。`YYYY-MM-DD`形式（例：`2026-07-10`） | 実際にサービスを開始したい日（またはそれ以降の日） |
| `TEST_MAIL_TO` | 設定されている間、すべてのメールの宛先をこのアドレスに強制的に差し替える（お客様には届かなくなる）テスト用スイッチ | 空欄のまま（試運転の途中で使う。詳しくは`MANUAL_DAILY.md`参照） |
| `BRIDGE_URL` | メール送信を依頼する先（3章で設置したSMTPブリッジ）のURL | 設置したブリッジのURL（`.php`で終わるアドレス） |
| `BRIDGE_SECRET` | ブリッジへの依頼が正規のものであることを証明する合言葉。3章の`config.php`内`bridge_secret`と**必ず同じ値**にする | ブリッジ側と同じ合言葉 |
| `ADMIN_EMAIL` | エラー通知・月次レポートの送信先。運用担当者のメールアドレス | 運用担当者の実際のメールアドレス |
| `ADMIN_TOKEN` | 管理者用の操作（テナント作成・アクセストークン発行）を許可するための合言葉 | 十分に長いランダムな文字列（**エンジニアに生成を依頼することを推奨**） |
| `TENANT_MASTER_SHEET_ID` | 全店舗の一覧を管理する「マスター管理シート」のID | マスター管理シートのURLに含まれるID部分 |
| `API_KEY_SHEET_ID` | 楽天RMSの認証情報（3章で取得したlicenseKey・serviceSecret）を保存したシートのID | 該当シートのURLに含まれるID部分 |
| `EXCLUDE_ORDERS` | 特定の注文番号を一時的にフォローメール対象から除外する緊急ブレーキ（カンマ区切りで注文番号を並べる） | 空欄のまま（トラブル発生時にのみ使う一時的な項目） |
| `SHOP_SIGNATURE__OVERRIDE` | メール末尾の署名を、自動生成の代わりに固定の文章で上書きしたいときだけ使う項目 | 空欄のまま（通常は自動生成に任せる） |

失敗するとどうなるか（代表例）：
- `BRIDGE_URL`または`BRIDGE_SECRET`が空欄・間違いのままだと、メール送信のたびにエラーになり、お客様にメールが届きません。
- `GO_LIVE_DATE`を空欄や不正な文字列のままにすると、フォローメール送信対象が常に0件になります（安全のため「わからない場合は何もしない」という設計です）。

間違えたときの戻し方：該当するキーの「値」欄をクリックして正しい値に上書きし、保存すればすぐに反映されます（`DRY_RUN`や`TEST_MAIL_TO`はキャッシュを持たないため、次にステップ侍が動いた瞬間から新しい値が使われます）。

## 7. トリガー（自動実行のスケジュール）を登録する

設定がすべて終わり、`MANUAL_DAILY.md`の「テスト運用の3段階」を経て本番投入の準備ができたら、最後にトリガーを登録します。**この手順は本番稼働の直前に行うものであり、初期設定の最後のステップとして紹介しますが、実際に登録するタイミングは`MANUAL_DAILY.md`の指示に従ってください。**

1. GASエディタ左側のメニューから、時計のアイコン「トリガー」をクリックする。
2. 右下の「トリガーを追加」ボタンをクリックする。
3. 「実行する関数を選択」から `runHourlyFollowPipeline` を選ぶ。
   - なぜ：この関数が「受注取得→レビュー紐づけ→フォローメール送信」を1時間ごとに自動で行う本体だからです。**`runPipeline`という似た名前の関数もありますが、そちらはクーポン機能（準備中）も一緒に動かしてしまうため、今は選ばないでください。**
4. 「イベントのソースを選択」で「時間主導型」を選び、「1時間おきタイマー」を選んで保存する。

【スクショ: GASエディタのトリガー追加画面（runHourlyFollowPipelineを選択した状態）】

失敗するとどうなるか：`runPipeline`を誤って登録すると、準備中のクーポン発行処理まで動き出してしまう可能性があります。

間違えたときの戻し方：トリガー一覧の該当行の右側にある「⋮」（縦三点リーダー）から「トリガーを削除」を選べば、即座に自動実行が止まります。
